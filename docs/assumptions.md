# 仮定・未確定事項

最終更新: 2026-07-27

この文書では、実装を止めずに進めるための仮定と、その検証方法を記録する。
未検証事項を事実として利用者へ表示しない。

## 採用した仮定

1. 主データは東京都都市整備局「新宿駅周辺の施設情報等」令和5年2月改訂版とする。
   同データは新宿駅の階層別地図、施設情報、Nav Node、Nav Link を同じ版で提供するため、
   広域ネットワークと手作業の地点だけを組み合わせるより本 MVP に適する。
2. API 境界の座標は EPSG:4326 とする。仕様書が距離をメートルと定義しているため、
   正常な Nav Link の `dm` はメートルとして採用する。不正・欠損時のみ WGS84 測地線距離を
   使用し、緯度経度の単純なユークリッド距離は使わない。
3. 歩行速度は 80 m/分とし、所要時間は参考値として表示する。待ち時間、混雑、信号、
   エレベーター待ち時間は含めない。
4. スナップ警告閾値は 15 m、処理拒否閾値は 50 m を初期値とする。公開施設がネットワークへ
   直接関連付く場合は関連 ID を優先し、座標最近傍はフォールバックとする。
5. 左右案内は、分岐前後の線形と地図方位を十分に確定できる場合だけ生成する。
   初期版では安全側に倒し、原則として「分岐を次の通路へ進む」と表現する。
6. 写真 URL と PLATEAU URL は nullable とする。第三者写真を取得・埋め込みせず、
   写真がなくてもランドマーク名と説明だけで動作させる。
7. 初期版の対象地は東京都公開 ZIP に含まれる範囲とする。他の版の国土交通省ネットワークと
   自動結合しない。
8. 地図背景は公開データに含まれる階層図形を優先し、利用規約を確認していない外部タイルを
   暗黙に利用しない。
9. `platform_gate_mapping_template.csv` は未検証レコードを既定で非表示にする。
   `verified=true` と根拠 URL/注記が揃った行だけを将来の案内候補として扱う。

## 現時点で確認できていない事項

1. ZIP 内で改札・出口を識別する正確なカテゴリ名と、日本語名称の網羅性。
2. 各 Nav Link の設備種別（階段、エスカレーター、エレベーター）がどこまで属性化されているか。
3. レベル ID と現地表記 `B2`、`B1`、`1F` の完全な対応。
4. 公開時点以降の工事、閉鎖、営業時間、通行方向、改札名・出口名の変更。
5. 公開データ上の経路が現在も物理的に連続しているか。
6. 現地案内サインとランドマーク候補の一致。
7. `ui_mock.html` と Colab ノートブックはワークスペースに見つからないため、その内容。

## 解消方法

- ZIP と仕様書を ETL テストで照合する。
- 自動分類レポートを `data/processed/` に出力し、曖昧な項目を一覧化する。
- 手動補正は `data/overrides/` に `evidence_url`、`verified_at`、`note` と共に記録する。
- 提出前に複数経路を現地確認し、`docs/data-audit.md` を更新する。
